# TV Pro — تطبيق سطح المكتب (macOS أولًا، Windows لاحقًا)

هذا المجلد (`desktop/`) يحتوي تطبيق Electron رسمي يغلّف موقع TV Pro (`tv-pro.app`) الحالي في تطبيق سطح مكتب حقيقي،
بدون المساس بالموقع نفسه إطلاقًا. كل ملفات سطح المكتب معزولة هنا، والموقع يستمر بالعمل كما هو تمامًا.

## الفكرة باختصار

- يُنشئ التطبيق نسخة من ملفات الموقع الثابتة (`index.html`, `_next/`, الأيقونات...) داخل `desktop/site/` (هذا
  المجلد يُبنى تلقائيًا ولا يُحفظ في Git).
- يُقدَّم هذا الموقع المحلي عبر بروتوكول خاص آمن `app://tvpro/` بدل `file://`، حتى تعمل fetch والمسارات النسبية
  تمامًا كموقع حقيقي عبر HTTPS.
- تعديل واحد صغير فقط يُضاف تلقائيًا إلى النسخة المحلية من الحزمة: تفضيل بوابة محلية (تعمل داخل التطبيق نفسه،
  انظر أدناه) قبل البوابات الخارجية (Cloudflare/Deno) إن توفرت. الموقع المباشر على tv-pro.app لا يتأثر بهذا إطلاقًا.
- لا توجد بيانات اشتراك أو حسابات تجريبية داخل الكود في أي مكان.

## المتطلبات

- **Node.js 18 أو أحدث** (تم تطويره واختباره هنا بـ Node 22).
- **لبناء DMG فعليًا: جهاز Mac حقيقي.** هذا ليس اختياريًا — راجع قسم "ما الذي لم يُختبر ولماذا" أدناه.

## التشغيل أثناء التطوير (macOS)

```bash
cd desktop
npm install
npm run dev
```

هذا يبني نسخة الموقع المحلية تلقائيًا (`predev` يستدعي `build:site`) ثم يفتح التطبيق مع أدوات المطوّر. أي تعديل
على ملفات الموقع في جذر المستودع يحتاج إعادة تشغيل `npm run dev` ليُنسخ من جديد (أو نفّذ `npm run build:site`
يدويًا ثم أعد تشغيل التطبيق).

```bash
npm start   # تشغيل عادي بدون أدوات المطوّر
```

## بناء نسخة macOS (.app و .dmg)

على جهاز Mac (ضروري لـ DMG، راجع القسم التالي):

```bash
cd desktop
npm install
npm run dist:mac          # Universal (Apple Silicon + Intel) إن كان مدعومًا على جهازك
# أو فصل كل معمارية على حدة:
npm run dist:mac:arm64    # Apple Silicon فقط
npm run dist:mac:x64      # Intel فقط
```

**ملف DMG الناتج يكون في**: `desktop/dist/TV Pro-<version>.dmg` (و `desktop/dist/mac/TV Pro.app` للنسخة غير
المضغوطة). يُبنى أيضًا ملف `.zip` للتحديثات التلقائية المستقبلية إن احتجتها.

كل أمر `dist:mac*` يستدعي تلقائيًا بناء نسخة الموقع (`build:site`) وتوليد أيقونة `.icns` من شعار الموقع
(`build:icons`) قبل التعبئة، فلا حاجة لتشغيلهما يدويًا إلا إذا أردت نسخة أحدث فورًا لسبب ما.

## التوقيع (Code Signing) وNotarization — **هام جدًا**

النسخة التي يبنيها هذا الإعداد افتراضيًا هي **نسخة محلية غير موقّعة رسميًا (ad-hoc فقط)**. ستعمل على جهازك
مباشرة، لكن توزيعها على أجهزة أخرى سيُظهر تحذير Gatekeeper ("لا يمكن التحقق من المطوّر"). الفرق بين النسختين:

| | نسخة محلية (الافتراضي هنا) | نسخة موزَّعة رسميًا |
|---|---|---|
| التوقيع | ad-hoc تلقائي من electron-builder (أو بلا توقيع إن شُغِّل من غير macOS) | شهادة **Developer ID Application** من Apple |
| Notarization | غير مطلوبة | **مطلوبة** من Apple قبل التوزيع العام |
| تشغيلها على جهازك أنت | يعمل مباشرة | يعمل مباشرة |
| تشغيلها على جهاز شخص آخر | تحذير Gatekeeper، يحتاج "فتح رغم التحذير" يدويًا من إعدادات الأمان | تعمل بلا أي تحذير |

لتوزيعها رسميًا لاحقًا، تحتاج:
1. **عضوية Apple Developer Program** (مدفوعة سنويًا).
2. شهادة **Developer ID Application** من Xcode/Apple Developer portal.
3. تعيين متغيرات البيئة التالية قبل البناء (electron-builder يلتقطها تلقائيًا):
   ```bash
   export CSC_LINK=/path/to/certificate.p12
   export CSC_KEY_PASSWORD="..."
   export APPLE_ID="you@example.com"
   export APPLE_APP_SPECIFIC_PASSWORD="...."   # كلمة مرور خاصة بالتطبيقات من appleid.apple.com
   export APPLE_TEAM_ID="XXXXXXXXXX"
   npm run dist:mac
   ```
4. عند توفر هذه المتغيرات فعّل notarization في `package.json` (`build.mac.notarize`) — لم أفعّلها افتراضيًا هنا
   لأنها تفشل بدون شهادة حقيقية، ولا أملك شهادتك لأختبرها.

**لم أقم بأي توقيع أو notarization فعلي** — لا أملك شهادة Apple Developer، ولا يمكن تنفيذ أي من هذا من بيئة
Linux المعزولة التي عملت فيها أصلًا.

## مسح البيانات وتسجيل الخروج

من القائمة العلوية (macOS): **TV Pro ← مسح بيانات الاشتراك المحفوظة محليًا…**. هذا يطلب تأكيدًا، ثم يمسح:
- بيانات الاعتماد المخزَّنة في مخزن النظام الآمن (macOS Keychain عبر `safeStorage`)، إن استُخدم هذا المخزن.
- كل بيانات الموقع نفسه (IndexedDB، localStorage، الكاش) داخل التطبيق فقط — لا يمسّ هذا حسابك لدى مزوّد IPTV،
  فقط ما هو محفوظ على هذا الجهاز.

## الأمان — ما الذي طُبِّق وكيف تتحقق منه

- `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false` على نافذة التطبيق الوحيدة — راجع
  `src/main.js`. تحقّق سريع: `window.require` و`window.process` غير موجودين داخل صفحة الموقع (مُختبَر في
  `scripts/smoke-test.js`).
- لا تواصل مباشر بين الصفحة وNode: كل ما هو متاح للصفحة يمر عبر `src/preload.js` (`window.tvproDesktop`)، وكل
  قناة IPC في `src/ipcHandlers.js` تتحقق من مصدر المرسل (`senderFrame.url` يجب أن يبدأ بـ `app://`) ومن شكل
  المدخلات قبل التنفيذ.
- `webSecurity` يبقى `true` دائمًا؛ لم أعطّله في أي مكان ولم أتجاهل أخطاء الشهادات عالميًا.
- أي تنقّل أو نافذة جديدة لرابط خارج `app://` تُفتح في متصفحك الافتراضي بدل نافذة التطبيق (`will-navigate`
  و`setWindowOpenHandler` في `src/main.js`)، ولا يُفتح رابط إلا إذا كان `https://` فعليًا.
- بيانات الاشتراك الحساسة (إن استُخدم مخزن سطح المكتب لها) تُشفَّر عبر `safeStorage` (مبني على macOS Keychain) —
  لا تُكتب كنص صريح على القرص أبدًا، ولا تظهر في أي `console.log` أو سجلّ (راجع `src/secureStore.js`: لا يوجد أي
  سطر يطبع قيمة، فقط أسماء المفاتيح والنتائج المنطقية).
- البوابة المحلية (`src/localProxy.js`) مربوطة حصرًا بـ `127.0.0.1` (لا `0.0.0.0` أبدًا)، وتعيد استخدام نفس منطق
  التحقق من الوجهات (حظر العناوين الداخلية/الخاصة، حدود إعادة التوجيه) الموجود فعليًا في `tvpro-gateway-deno.ts`
  المنشور والمُختبَر — لم يُكتب أي منطق تحقق جديد، فقط أعيد استخدام الكود المُتحقَّق منه مسبقًا.

## البوابة المحلية — لماذا ومتى تُستخدم

الموقع (وتطبيق سطح المكتب أيضًا) يحتاج بوابة شبكة فقط عندما يكون مصدر IPTV عبر HTTP عاديًا (وليس HTTPS)، بسبب
قيود المتصفح (Mixed Content وCORS) — هذا قيد من Chromium نفسه، وتطبيق Electron لا "يحل" هذا القيد لأنه لا يزال
يستخدم محرك Chromium لعرض الصفحة. ما يضيفه تطبيق سطح المكتب تحديدًا هو **بوابة إضافية تعمل محليًا داخل التطبيق
نفسه** (عملية Node في الخلفية، منفذ عشوائي على 127.0.0.1 فقط)، تُفضَّل أولًا إن نجحت، وإلا يرجع التطبيق تلقائيًا
لنفس بوابات Cloudflare/Deno الخارجية التي يستخدمها الموقع. **لا وعد بأن هذا يحل مشاكل مزوّد الاشتراك نفسه** (حظر
IP، حد اتصال واحد، قنوات معطّلة من عنده) — هذه قيود خارج نطاق أي تطبيق، كما هو موثّق في `PLAYBACK-INVESTIGATION.md`
في جذر المستودع.

## تشغيل الفيديو — ما تحقّقت منه فعليًا وما لم أفترضه

- المشغّل نفسه (HLS عبر hls.js أو native HLS، MP4 مباشرة...) هو **نفس مشغّل الموقع تمامًا**، لم أستبدله ولم
  أعدّله. Electron يستخدم نفس محرك Chromium، فكل صيغة تعمل في Chrome ستعمل هنا بنفس السلوك تمامًا — وأي صيغة لا
  يدعمها Chromium (MKV، بعض ملفات HEVC) **لن تعمل هنا أيضًا**، ولم أفترض عكس ذلك. خيارات "افتح في VLC/Infuse"
  الموجودة في الموقع تبقى الحل لهذه الحالة (ملاحظة: روابط `vlc-x-callback://`/`infuse://` هذه مصمَّمة لـ iOS؛
  على سطح مكتب ستحتاج غالبًا تثبيت تطبيق VLC لسطح المكتب وتشغيل الرابط عبر "نسخ الرابط" بدل زر "افتح في VLC"
  المباشر — لم أعدّل هذا الجزء لأنه خارج نطاق هذا الإصدار، وأوثقه هنا بصراحة كحد معروف).
- لم أدّعِ اختبار أي صيغة فعليًا ضد اشتراك IPTV حقيقي من هذه البيئة (لا يوجد اتصال شبكة مسموح به لمزوّدي IPTV من
  بيئة التطوير المعزولة). ما اختبرته فعليًا: أن نافذة Electron تُحمّل صفحة الموقع كاملة بنجاح (`did-finish-load`)،
  وأن تحويلها بروتوكول `app://` لا يكسر أي شيء بنيويًا — وهذا تحقّق من آلية العرض، وليس تحقّقًا من تشغيل بث حقيقي.

## ما الذي اختبرته فعليًا من بيئة التطوير (Linux، بدون macOS)

بيئة العمل هذه Linux بدون شاشة حقيقية ولا عتاد Apple، لذا **لم أستطع** اختبار أي سلوك خاص بـ macOS (Dock، القائمة
الأصلية الفعلية، إشعارات النظام، DMG الفعلي، التوقيع، Notarization). ما اختبرته فعليًا، وبنتائج حقيقية:

1. **منطق البوابة المحلية بمعزل عن Electron** (`npm run test:local-proxy`): يبدأ خادمًا حقيقيًا على 127.0.0.1،
   يعيد كتابة قائمة تشغيل حقيقية عبر مقبس شبكة حقيقي، ويرفض عنوان IP داخلي (SSRF) — **نجح**.
2. **تشغيل Electron الحقيقي تحت Xvfb (خادم عرض افتراضي على Linux)** (`npm run smoke`؛ يحتاج
   `xvfb-run -a npm run smoke` إن كانت البيئة بلا شاشة، كما هنا): يبني نافذة حقيقية، يحمّل `desktop/site` عبر
   `app://`، يتحقق أن `window.tvproDesktop` موجود وأن `require`/`process` غير مسرَّبين للصفحة، تحقق round-trip
   كامل عبر IPC، وتحقق أن تخزين بيانات الاعتماد يرفض العمل بأمان عند غياب keychain النظام (كما في هذا الحاوي) —
   **نجحت كل الفحوصات**.
3. **تشغيل التطبيق الحقيقي كاملًا لعدة ثوانٍ** تحت Xvfb: لم يتعطّل، حمّل صفحة تسجيل الدخول الحقيقية للموقع،
   وحاول فعليًا الاتصال ببوابات Cloudflare/Deno الخارجية (رُفضت هذه الاتصالات فقط بسبب سياسة شبكة بيئة التطوير
   نفسها، لا بسبب كود التطبيق).
4. **تعبئة .app فعلية لـ macOS من Linux** (`npm run dist:mac:x64`؛ نعم، هذا ممكن جزئيًا): أنتج فعليًا
   `TV Pro.app` ببنية صحيحة (Info.plist، أيقونة، app.asar)، لكن **غير موقَّع** (المُخرَج صراحة:
   "skipped macOS application code signing: reason=supported only on macOS").
5. **محاولة بناء DMG فعلي من Linux**: **فشلت فعليًا وبشكل متوقَّع** — الحزمة `dmg-license` التي تحتاجها أداة
   `dmg-builder` هي تبعية اختيارية مقيَّدة لنظام macOS فقط (`"os": ["darwin"]`)، فلم تُثبَّت على Linux أصلًا. هذا
   تأكيد تقني حقيقي، وليس افتراضًا، لحاجة DMG فعلًا لجهاز Mac. **ما يتبقى لك فعله على جهازك: تشغيل
   `npm run dist:mac` هناك للحصول على DMG فعلي، ثم اختبار التثبيت والتشغيل والـDock وملء الشاشة وPiP فعليًا.**

## البنية

```
desktop/
  package.json           تبعيات ونصوص npm وإعداد electron-builder
  src/
    main.js              دورة حياة التطبيق، النافذة، القائمة، بروتوكول app://، البوابة المحلية
    preload.js            contextBridge الوحيد الذي تراه الصفحة
    ipcHandlers.js         كل قنوات IPC + التحقق من المرسل
    secureStore.js         تخزين بيانات الاعتماد المشفَّر (safeStorage)
    localProxy.js          البوابة المحلية (127.0.0.1 فقط) المبنية على tvpro-gateway-deno.ts نفسه
    appProtocol.js         تسجيل وتقديم app://tvpro/ مع حماية من path traversal
    windowState.js         حفظ/استرجاع حجم وموضع النافذة
    menu.js                القائمة الأصلية بالعربية
    loading.html            شاشة تحميل محلية بسيطة (شعار + دوّارة) قبل ظهور الموقع
  scripts/
    build-site.js          ينسخ الموقع من الجذر إلى desktop/site + تعديل إضافي واحد صغير (بوابة محلية)
    build-icons.js         يبني icon.icns/icon.ico من شعار الموقع (بدون أدوات macOS)
    smoke-test.js           اختبار Electron حقيقي تحت Xvfb (انظر أعلاه)
    test-local-proxy.js     اختبار Node بحت للبوابة المحلية (بدون Electron)
  build/
    entitlements.mac.plist  صلاحيات hardened runtime اللازمة لاحقًا للـnotarization
    icon.icns / icon.ico    تُبنى تلقائيًا، غير محفوظة في Git
```

## الخطوات المتبقية على جهازك (Mac)

1. `cd desktop && npm install`
2. `npm run dev` — تأكد أن النافذة تظهر في Dock، القائمة أصلية، تغيير الحجم وحفظه يعمل، إعادة فتح النافذة بالضغط
   على أيقونة Dock يعمل، ملء الشاشة وPiP في المشغّل يعملان، والعربية/الإنجليزية والوضع الداكن/الفاتح كما في
   الموقع تمامًا (لم أغيّر شيئًا هنا، فيجب أن يتطابق تمامًا مع ما تراه في المتصفح).
3. جرّب تسجيل الدخول باشتراكك الحقيقي (Xtream أو M3U) وشغّل قناة/فيلمًا فعليًا — هذا أول اختبار تشغيل حقيقي ممكن،
   ولم أستطع إجراءه من هنا إطلاقًا.
4. `npm run dist:mac` (أو `dist:mac:arm64`/`dist:mac:x64` لمعمارية واحدة) للحصول على DMG فعلي، وجرّب التثبيت منه.
5. إن أردت التوزيع لغير جهازك: احصل على شهادة Developer ID ونفّذ خطوات Notarization أعلاه.
